# D1 回迁评估（2026-10-14）

状态：没有切换测试站或正式站，没有创建/写入新的远程 D1 数据库。当前线上故障先在既有 Turso 测试站修复，保留已有下载和 R2 文件。

## 免费额度与本地证据

[D1 官方定价](https://developers.cloudflare.com/d1/platform/pricing/)：每账号每日 5,000,000 行读取、100,000 行写入，UTC 零点重置。索引变更也增加写入行数；应用的 200,000 请求/SQL 保护不能增加供应商额度。

2026-10-14，在实际 workerd/D1 本地模拟器运行现有普通新图片下载路径，读取每条执行结果的 `meta.rows_read/rows_written`，得到 **6 条 SQL、32 行读取、21 行写入**。测试同时验证真实图片已存入本地 R2、任务已完成。它是这一条本地路径的元数据测量，不是线上 D1 账单，也不能替代不同来源、失败重试和大库下的实测。

按该样本粗算，100,000 / 21 约为 4,761 张新图/日，尚未扣除创建图片任务、章节提交、其他用户和读取进度等消耗。直接把现在逐图片存储作业状态的模型切回免费 D1，可能在整部作品下载完之前再次耗尽当日额度。不能承诺仅切换绑定就会像原本本地 SQLite 一样快。

## 可实施的迁移顺序

1. 先将逐图片的领取、失败次数、完成标志和恢复检查点移至私有 R2 控制记录，保留租约、取消、权限、重试上限和完整性检查。D1 只保存用户、分组权限、作品、章节、阅读进度和章节级作业状态。界面和阅读图片路径不变。
2. 用同一来源实测一章和整部下载的 D1 `rows_read/rows_written`；检查常用 SQL 的执行计划和索引，并计入触发器、索引、失败与重试。远程测试前执行账号 Analytics 预算检查，预算不可读取或接近免费上限时不写库。
3. 在短维护窗口冻结写入/队列领取，从 Turso 导出一致快照，包含用户哈希、权限、作品/章节标识、进度、阅读时长和设置。文件及 R2 key 原样保留；私有备份与凭据不提交 GitHub，不作为公开 Actions 产物。
4. 初始化独立的 D1 目标库，分批导入业务数据和章节级未完成作业，记录检查点。历史逐图片作业不重复写入 D1；其恢复信息转存 R2。R2 存储预算按迁移清单核对重叠对象、存储总量和有效预留。
5. 部署明确绑定旧 R2 桶的新测试 Worker，保持测试与正式资源隔离。默认部署脚本会根据数据库类型创建不同的桶/队列，不能只改 `DATABASE_PROVIDER` 就当作数据迁移完成。
6. 核验每个章节 manifest 与 R2 图片、首尾页读取、用户/分组权限、进度写入读回、取消/删除，以及原手机/电脑界面；整部真实下载通过后再切换测试入口。
7. 保留 Turso 一致快照及旧部署。切换后的数据采用检查点回填或增量导出再回退；不能让两个后端同时下载同一作品，也不能用旧控制计数重新放大当天额度。

免费 D1 的合适目标是减少到章节级写入。保留当前逐图片 SQL 模型但要提高 D1 硬额度，则需要 Workers Paid（官方基础价格从每月 $5 起），本任务不会自动升级。漫画/小说文件 10–100 GB 仍放 R2，超过每账号共享的 10 GB 免费存储部分另计费用。
